# 日常功能开发

先完成最小调查，再写代码。不要把相似页面当成可复制模板。

## 改动地图

- 确认用户行为、入口、目标文件、直接调用链、状态和 API 边界。
- 找出已有筛选、表格、弹框、表单、权限、导航、导入导出、缓存和 loading 的实际实现。
- 搜索并读取最相关的 1～3 个已有能力和至少一个真实调用方；详情见 `capability-discovery.md`。
- 说明预计修改/新增文件、复用结论和不复用的具体原因。普通任务保持 3～5 行。

## 实现顺序

1. 先确认请求、响应、权限、成功、失败和刷新语义；接口驱动功能读 `delivery-readiness.md`。
2. 在现有页面状态和请求边界完成最小实现。明确构造表单和请求 DTO，不修改响应对象充当成功状态。
3. 复用契约一致的能力；如果不一致且共享会扩大条件分支，保留局部实现。
4. 补齐用户可见操作的 loading、防重复、失败反馈、成功后的权威刷新、空状态和重置行为。
5. 完成后按 `pre-submit-checks.md` 做与风险相称的验证。

## 范围控制

未明确要求重构时，历史大文件、旧调用方和无关重复都不在本次范围。不要为了“通用化”迁移调用方；不要新增只转发 props/events 的薄组件。
