# 工程实现边界

## 契约与数据

- 已确认字段、层级和类型时直接消费，不保留无依据的别名、镜像对象、类型兜底或重复请求。
- 从响应显式构造表单；在请求边界显式构造 DTO。不要 `form = row`，也不要原样提交 UI 状态。
- 空值、`0`、空数组和未配置必须按已知语义处理，不能用 `||`、名称匹配、首项或“多字段兼容”掩盖业务不确定性。
- 需要详情语义时按稳定 ID 读权威详情，不用列表缓存或大 limit 列表模拟详情。

## 组件与复用

- 子组件消费稳定的 props/events 契约；父层处理后端 DTO 到组件模型的转换。
- 修改公共组件前枚举调用方，比较默认值、事件、slots、ref、返回结构、样式与触发时机。
- 新行为优先使用默认关闭的可选参数，确保旧调用方不变；无法确认兼容性时不要“顺便统一”。
- 新组件需要独立交互/状态边界或真实兼容调用方。文件长、字段多和未来可能复用都不是充分理由。

## 通用风险

- 列表：筛选变化重置分页；重置清除全部相关字段；统计、导出和查询使用同一筛选条件。
- 弹框：复制编辑行；提交后由权威数据刷新；关闭只清理真实临时状态。
- 权限：区分路由、元素、动态区域和会在挂载时发请求的组件实例化。
- CSS：删除或修改前搜索模板、render、动态 class、深度选择器和全局覆盖。
