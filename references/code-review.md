# 前端 Code Review

先确定范围：工作区、提交、分支、目录或模块。阅读完整 diff 和上下文，不以文件名、lint 或编译通过替代行为审计。

## 检查顺序

1. 从用户入口追踪到 handler、状态、子组件、请求和成功/失败路径。
2. 核对 `engineering-guardrails.md`：DTO、表单边界、组件契约、隐藏兜底、抽象和范围。
3. API 驱动功能核对 `delivery-readiness.md` 的完整闭环。
4. 多列表、字典或关联逻辑核对 `data-contract-debugging.md`。
5. 新 UI/公共能力核对 `capability-discovery.md` 的复用选择和调用方证据。

## 公共影响分析

若变更公共组件、hooks/composables、utils、状态、路由、请求层、样式，或文件有多个调用方：

- 搜索 import、模板标签、包装组件、事件透传、ref 和样式覆盖。
- 比较 props、默认值、事件、时机、slots、返回结构和共享状态。
- 验证旧默认调用方、新调用方及最容易受影响的嵌套/权限路径。
- 输出调用方范围、兼容方式、已验证项和明确残余风险。

按严重程度输出问题，每项给出位置、证据、用户影响和具体修复方式；最后列出未覆盖范围。
