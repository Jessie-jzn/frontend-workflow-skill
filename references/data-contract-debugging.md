# 关联数据契约与展示排查

跨响应列表拼展示行时，只使用接口明确的稳定关联键和基数。不能依据名称、数组顺序、部分字段、最高匹配分或“取第一条”推断归属。

1. 写清最终行数由哪组主数据决定，以及每列来自哪里。
2. 确认一对一、一对多或多对多，关联键是否唯一、可空、必返。
3. 用真实值区分：字段缺失、值为空、值不一致、键不唯一和多匹配。
4. 未匹配行保持可见并显示明确空态；不得 `filter(Boolean)` 后伪装成正常空列表。
5. 缺稳定关系时要求接口返回外键、映射或嵌套明细；不要在前端使用启发式补齐。

`String(a) === String(b)` 只能处理已确认的类型差异，不能修复语义不一致；`null` 也不是通配符。
